# 截图 / 粘贴识题：实现与本机验证

初版记录为 v0.2.0，更新至 2026-10-14 的 v0.2.6 Windows 验证。已实现桌面截图识题和复制粘贴识题两条入口；Mac 历史记录保留，Windows 本轮的范围与证据见 [Windows 验证报告](Windows验证报告.md)。

## 使用方法

1. 选择需要查询的题库。在详细模式点击「截图识题」，或在任一模式点击搜索框右侧扫描图标；应用内也可按 `⌘⇧O` / `Ctrl+Shift+O`。
2. Mac 点击「截取屏幕」：窗口暂时隐藏，截取主屏幕，再回到程序中框选一道题的题干和选项，松开鼠标自动识别。另一块屏幕上的内容可用系统截图后粘贴。
3. 复制题目图片或文字后，在题库窗口按 `⌘V` / `Ctrl+V`。完整题目自动打开识题面板；普通短关键词继续用于搜索。已有面板也提供「粘贴识别」按钮、文件选择和图片拖入。
4. OCR 完成后自动查询当前题库。可以直接修改左侧错字，停顿约 200 毫秒后重新匹配。选择其他题库会重新查询，旧请求不会覆盖当前结果。
5. 题干与选项一致时直接显示答案。选项换序按内容对应字母；近似题先展示候选，点选后查看题库答案与完整题目。未完全对应的选项显示原题库字母和选项内容。

Mac 首次截图可能需要在「系统设置 → 隐私与安全性 → 屏幕与系统音频录制」允许题库，按系统提示重开应用；也可先用系统截图复制到剪贴板，再粘贴识别。应用只在主动点击截图或粘贴时读取这些内容，没有后台剪贴板监控。

## 识别引擎与平台

| 路径 | 当前实现 | 验证状态 |
| --- | --- | --- |
| macOS 系统 OCR | Apple Vision `VNRecognizeTextRequest`，优先简体中文、繁体中文与英语，保留文字行和坐标 | 本机实际运行通过 |
| Mac 截图 | 系统截图工具截取主屏幕，应用内按原图坐标裁切，再识别选中区域 | 实际框选与显示答案通过 |
| Windows 系统 OCR | `Windows.Media.Ocr`，识别前按系统最大尺寸缩放；需要可用语言包和运行环境 | Windows 11 x64 实际应用识别三张 PNG 并返回正确候选；有差异时保留人工确认 |
| Windows 截图 | 启动系统截图工具 `ms-screenclip:`，等待剪贴板出现新图；支持 Esc / 超时恢复窗口 | 代码与接口检查通过；未实机验证 |
| 原生剪贴板 | Mac PNG / TIFF / 文字；Windows RGBA 图片 / 文字 | Mac 保留此前验证；Windows 已实测图片 / 完整文字 Ctrl+V、按钮读取和图片拖入 |
| 内置 OCR | Tesseract.js 7，简体中文 + 英语，Worker / WASM / 模型随应用打包 | Mac WebView 与 Windows WebView2 均实际识别成功，无运行时 CDN 依赖；Windows 取消和重新匹配通过 |

自动模式在系统 OCR 报错或未返回文字时切换内置引擎；系统返回错字仍可手动改字或切换引擎重试，不会把“返回了文字”视为准确性证明。系统首次识别可能有初始化耗时。本机首次调用约 14～15 秒，后续短题曾测得约 0.12 秒；样本量不足以形成 OCR 时延保证。

用户已允许使用在线方案。本版用系统与随程序打包的引擎完成闭环，没有配置云 OCR 服务、上传图片或要求购买接口。后续在线引擎可接入同一识别结果结构，需另行选择服务、设置密钥和图片处理方式。

## 题目匹配与答案

匹配限定所选题库的未删除题目。先用完整题干查 FTS 索引；无完整命中时，采样短片段与长片段、合并有限数量的候选，再比较题干及选项。每个片段最多读取 129 条候选记录，最多解码 200 道题，页面最多显示 8 道候选，避免为每次识题加载整个题库或对大量常见命中做全量排序。这是有界候选检索，不保证各种残缺截图都能召回。

题号、题型和尾部「答案／解析」先拆分；正文保留大小写、否定词、数字、小数、运算符、标点和引号内容，避免把代码含义不同的题直接判为一致。版式空白可归一化，字符串内空白保留。匹配分数仅用于排序，不作为校准过的正确概率展示。

当内容逐项对应且一对一时，才映射新的选项字母。例如原题 A、B、D 换序后变成 B、C、D，显示本次 B、C、D 及对应内容。多组题目、选项变化、相近题、缺答案或检索被截断时不直接展开自动答案。用户可点选候选查看库内答案。识题不会修改或补写正式题库；历史已确认答案仍按既有更正后的内容展示，不新增冲突标签。

## 验证记录

环境：MacBook Pro / Apple M4 / 16 GB，macOS 27.0.1，使用隔离目录 `.local/ocr-validation/`。识别样本取自项目现有题库并排成测试 PNG，位于 `tests/fixtures/ocr/`，不代表真实手机拍照样本集。

| 场景 | 观察结果 |
| --- | --- |
| 粘贴换序后的 M-015 完整文字 | 自动打开面板，答案映射为 B、C、D |
| 选择 M-015 换序 PNG，系统 OCR | 返回题干及四个选项，自动显示 B、C、D |
| 同一 PNG，内置 OCR | 成功返回文字；存在错字，M-015 / M-083 成为候选，先由使用者确认 |
| 最终交付应用内置 OCR，J-134 PNG | 0.30 秒返回文字，其中「沿」误成「治」；J-134 排在首位，点选后显示「正确」 |
| 预览中复制 J-134 图片，再快捷键粘贴 | 自动识别，显示「正确」 |
| 「粘贴识别」按钮读取图片 | 成功读取原生剪贴板并显示「正确」 |
| 截取屏幕、拖动框选 J-134 | 返回 1661 × 154 的裁切图；Apple Vision 识别约 15.21 秒，最终显示「正确」 |
| S-112 系统识别含错字 | 正确题目位于候选，不自动确信 |
| 单元与集成验证 | Rust OCR 8 项 + 题库核心 13 项通过；前端搜索片段与粘贴判断共 6 项通过 |

Rust 覆盖选项换序、不同题库和回收站、改动选项、否定词、数字、代码标点、大小写、引号与字符串空白、空答案、多组题目、无命中和超限输入。核心回归包含只读客户端再次制作离线包、版本更新回退以及四种格式往返。日志分别见 `artifacts/ocr-final-tests.log`、`artifacts/ocr-final-ui-tests.log`。

十万题匹配验证使用既有合成库，最终以交付应用内的 Release 版 `qbank-tool` 测量：

| 输入 | 样本数 | 首位命中 | 核心 P95 |
| --- | ---: | ---: | ---: |
| 完整题干与选项 | 20 | 20 | 83.53 ms |
| 替换题干中的一个字 | 5 | 5 | 54.70 ms |

报告为 `artifacts/ocr-match-100k-release.json` 和 `artifacts/ocr-match-100k-fuzzy-release.json`；先前开发构建报告保留为 `ocr-match-100k-final.json` 与 `ocr-match-100k-fuzzy-final.json`。它们只测 OCR 文字到候选的 Rust 核心查询，不含图片识别、剪贴板、截屏、IPC 或界面渲染；未清空系统缓存，样本数量有限，不能替代原有普通搜索验收，也不能把这些时延说成截图到答案的总耗时。

交付文件 `交付/题库_macOS_AppleSilicon_v0.2.0.zip` 为 18.48 MiB，应用签名与压缩包完整性检查均通过；最终应用已实际启动并复核文字粘贴、选项映射与内置 OCR。文件指纹及验证汇总在 `artifacts/ocr-delivery-validation.json`。

## 边界与后续验证

- 每次识别一道题；最多 20 MB、3000 万像素、16000 字。支持 PNG / JPEG / WebP。Mac 内置截图目前使用主屏幕。
- 清晰印刷体优先。倾斜、反光、低分辨率、复杂表格、公式、手写和缺少配图的题目尚未建立充分验收集。没有相机直连入口；已有拍照图片可以选择或粘贴。
- Windows 已完成完整编译、安装与实际 WebView2 / 系统 OCR / 剪贴板验证。系统截图框选、Esc / 超时恢复、多屏及 100% / 200% 缩放仍待人工检查；本机为 150%。缺少系统语言包的环境和自动回退分支未在本机制造并验证。
- 内置引擎取消时终止 Worker；系统 OCR 取消后忽略晚到的结果，底层系统请求可能继续至完成。截图取消或失败会恢复题库窗口。
- Mac 为本机临时签名应用，Windows 安装包未签名；尚未完成开发者签名、公证和公开分发验收。

内置语言数据来自 [tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast)，固定提交 `87416418657359cb625c412a48b6e1d6d41c29bd`。版本、SHA-256 和体积保存在 `assets/ocr/models.json`；许可证随资源打包。`scripts/prepare-ocr.mjs` 在构建前验证模型指纹，运行时不自动取最新版。
