其中检索差分测试将 777 道题、两个题库、回收站和多组复合检索结果，与直接扫描的预期记录逐一比较，检查记录顺序、分页和后续结果标记。

前端匹配片段测试 5 项通过，日志在 `artifacts/ui-presentation-tests.log`。覆盖题干与选项命中、解析及编号命中、全角字符、兼容字形扩展、组合附加符、引号短语、多个词的首个命中、换行压平，以及无命中时不展示系统 ID 等额外信息。

在实际 Mac 窗口中已验证：

- 从只读题库制作离线包，输出 `artifacts/UI阅读端再发布.qbank.zip`，复核题数与校验值。
- 从标准 Word 模板导入 3 道题，修改题干并即时检索，再删除和恢复题目。
- 最终交付目录中的 `.app` 已用正常数据目录直接启动，正确载入 914 题；详细模式与极速模式可切换。
- 极速模式限定当前题库，同一检索词在另一题库中不会串入结果；实际依次键入 `N → Na → Nav`，每个字符后结果均更新，全程未按回车。

标准 Excel 模板的四张工作表与 Word 模板的四页均已渲染并逐页检查；实际文件已通过应用同一套 Rust 解析器验证。Excel 的空白「题目」表不会误导入「示例」表。

## 5. 搜索性能

使用合成的独立题目，包含 20 个主题、251 组 API 标识、中文、代码与三类题型。不是将 914 题简单复制。200 个检索场景按三种顺序运行，共 600 次采样；覆盖短字、常用词、API、题号、多个词同时匹配及零命中。合成题平均可检索长度约 263–269 字符，不含图片或公式。

SQLite 测量包含打开连接、查询、读取首批题目及解码；界面测量从 React 搜索状态更新开始，经 IPC、SQLite 和结果渲染，再等待两次动画帧。界面测量不包含实体键盘事件派发和输入法组词耗时。没有清空操作系统缓存，不能称为严格冷启动结果。

## 8. v0.2.1 行内补全与多词高亮

极速模式仍优先从命中位置向后显示。若剩余文字不足一行，则按当前字体和题目列的实际宽度向前补充原题上下文；短题可完整显示，长题从前方省略，并尽量填满题目列。例如搜索「量」时，原先的「量。」现在显示「ArkTS中使用const声明常量。」，高亮落在句尾。题目本身不足一行时不添加重复文字。窗口宽度或字号变化会重新计算截取位置。

多词搜索按去重后的词顺序分配颜色，最多对应搜索接口支持的 12 个词。相同词在同一行的多个位置、不同题目和详细模式中保持同色；引号短语为同一词。重叠命中采用最靠前、同起点最长的片段。Unicode 归一化后的命中映射回原始字符，兼容字形和组合字符不会被切开。

验证情况：

- 前端 11 项测试通过，含原有片段规则、句尾完整短题、长题向前补足、不同宽度和字体测量、Unicode 边界、多词所有出现位置、重复词同色与重叠词规则。日志：`artifacts/search-display-tests.log`。
- TypeScript 检查、Mac Release 构建、本机签名与 ZIP 完整性校验通过。构建日志：`artifacts/search-display-build.log`。
- 实际 Mac 界面验证「量」的短题补全，以及「ArkTS const 量」的黄、蓝、粉三色高亮；超大字号／深色、中号／松绿均可读。详细模式使用同一套多词标记。复核时修正了字号切换后沿用旧字体宽度的问题。
- 最终构建使用独立十万题数据库，中号、松绿、极速模式，运行原有 200 个场景 × 3 轮，共 600 次。界面 P50 21 ms、P95 34 ms、P99 37 ms、最大 52 ms；核心查询 P95 4.75 ms。报告：`artifacts/bench-100k-speed-v0.2.1-ui.report.json`。

本次界面采样继续采用“React 状态更新 → IPC → SQLite → 渲染 → 两次动画帧”口径，没有清空系统缓存，也不含实体键盘派发。此次达到首批结果 P95 ≤ 100 ms；与旧批次的差异不能直接归因于本次显示逻辑。没有重跑百万题或 Windows 实机验证。题库数据、OCR 与离线包协议未作改动。

## 9. v0.2.2 搜索范围与命中片段

两种模式统一排除解析字段，详细模式的选项补齐多词高亮。已有数据库首次打开时自动将索引升级为 v3；重建和版本标记处于同一事务中，失败时回退，题目、解析、答案和题库版本不变。录入、导入、恢复及重新制包后的搜索遵守相同范围。

极速模式保持题干、选项的原始顺序。命中句尾时向前补足上下文，不再出现“天｜题干”式循环拼接。多个搜索词距离较远时，以省略号连接各个命中片段；先给每个词留出位置，再按可用宽度补上下文。多个搜索词自身的总宽度超过整行时，保留全文并允许题目单元格横向滚动。

本轮在用户要求将验证交由其本人之前，搜索范围与索引升级相关的 16 项核心测试、8 项 OCR 测试、12 项前端测试已通过。此后增加的命中片段调整仅随最终应用编译打包，未执行界面验证或重跑性能测试，不将此前通过结果视作最后一轮片段调整的验收。

用户验证步骤：

1. 详细模式搜“天”，打开 M-022、M-072 或 S-415，D 选项“聊天”的“天”应高亮。
2. 极速模式搜“天”，上述三题应向前补足原文，并以高亮的“天”结尾；不出现竖线和接回题干的文字。
3. 极速模式搜“用户 聊天”，两词应同时可见、颜色不同，中间距离过远时以“…”连接。缩窄窗口或切换字号后，两词仍应保留。
4. 在一份测试题的解析中填入“解析独有词”，保证题干、选项等其他字段没有该词。两种模式搜索均应无结果，打开该题仍能查看解析。

请退出旧窗口后打开新版。首次启动会自动更新已有题库的索引，无需重新导入。此次不安排代替用户进行的界面或性能验收。

## 12. v0.2.5 两种模式统一连续滚动

详细模式移除翻页按钮、页码、每页数量提示及对应状态和样式。两种模式共用连续加载组件逻辑，查询通过 `after_rowid` 接着读取，普通搜索接口不再使用偏移量翻页。滚动接近末尾时自动续载，查询条件变化后清空旧列表并回到开头；过期请求不会追加到新列表。

详细结果列表使用最多三行的题干预览和按字号调整的卡片高度，仅渲染可见区域附近的卡片。追加结果保持已选题目，`Alt + ↑ / ↓` 继续切换并让所选题目进入视野。读到末尾显示全部题目数量；失败时显示错误与重试入口。

该功能开发阶段仅编译打包，原有相关测试代码已改为游标续读接口；后续自动化回归结果见第 14 节。以下界面行为仍需实测：

1. 详细模式清空搜索，一直向下滚动超过第 50、100 题，确认自动续载且没有翻页控件。
2. 选择第 50 题以后的题目，确认右侧内容和答案对应正确；继续滚动加载时不自动换题。
3. 滚动较远后更换关键词、题型或题库，确认回到新列表开头，且不混入上一组结果；回收站同样可以连续滚动。
4. 滚动到末尾确认显示全部题目数量；切换极速模式，确认原有连续滚动仍可用。

## 13. v0.2.6 极速模式即时预览

设置按钮右侧新增「预览」开关，默认关闭，状态随显示设置保存。开启后，鼠标进入任意题目行就立即显示完整题干、所有选项、参考答案和已有解析，不设置停留计时。移到另一行立即换题，移出列表或按 Esc 关闭。预览直接使用当前结果中的题目内容，不重复查询数据库；解析只用于展示，仍不参与搜索。

预览按完整内容的实际排版高度计算尺寸，优先放在当前题目下方或上方，空间不足时自动加宽并调整位置。内容不截断、不折叠，也没有内部滚动条；极端情况下整张预览等比适配窗口。预览不拦截鼠标，连续移动和滚动列表可直接换题，不会因为覆盖题目而反复开关。

该功能开发阶段仅执行编译打包；后续自动化回归结果见第 14 节，未进行界面验收或性能测试。以下界面行为仍需实测：

1. 极速模式点击设置右侧的「预览」，鼠标直接移入不同题目，确认立即显示并立即切换，移出列表后消失；关闭开关后不再弹出。
2. 分别查看判断、单选、多选题，确认题干、所有选项和答案完整显示，已有解析也能看到；搜索多个词时题干、选项保持不同颜色高亮。
3. 将鼠标移到列表顶部、底部及左右边缘的题目，缩窄窗口或选择超大字号，确认预览自动调整宽度和位置、内容完整、没有内部滚动条。
4. 鼠标停在题目上滚动列表，确认预览对应鼠标下的新题；更换搜索词、切换模式或打开设置后不残留旧预览。重新打开程序，确认预览开关状态保留。
