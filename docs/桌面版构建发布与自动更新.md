# 桌面版构建发布与自动更新

## 构建与发布方式

正式版本由 GitHub Actions 原生构建：macOS 使用 Apple Silicon `macos-15`，Windows 使用 x64 `windows-2025`。推送 `vMAJOR.MINOR.PATCH` 标签后，工作流校验标签与应用版本一致，再并行构建两端；完成后创建一个包含两端下载文件、签名和校验和的 GitHub Release。

同一工作流可选地通过 SSH 把版本部署到自托管小主机。服务器文件先按版本号不可覆盖地保存，最后才原子更新 `latest.json`。该清单同时包含 `darwin-aarch64` 和 `windows-x86_64`，避免单平台发布覆盖另一个平台的更新入口。

更新地址为 `https://qbank.creart.top:8013/v1/desktop/latest.json`。现有 Caddy 静态路由已经覆盖 `/v1/desktop/*` 和 `/v1/desktop/releases/*`，发布脚本不改动 Caddy 配置。

## Windows 两种下载

- **Windows 安装版**：NSIS 安装程序，支持 Tauri 自动更新；更新会替换已安装程序，用户数据保存在系统用户目录，不随程序替换。WebView2 改为在线 bootstrapper，安装包不再捆绑约 127 MB 的离线运行时；Windows 10/11 通常已经提供 WebView2。安装时若设备没有运行时，需要联网下载安装。
- **Windows 便携版**：固定文件名 `题库_windows_x64_portable.exe`，仅作手动下载，不参与自动更新。重新下载后用新文件替换旧文件；用户数据仍在系统用户目录。

小主机上的下载路径按版本固定：Windows 安装版为 `/v1/desktop/releases/windows/<版本>/题库_windows_x64_setup.exe`，便携版为 `/v1/desktop/releases/windows/<版本>/题库_windows_x64_portable.exe`；macOS 手动安装包为 `/v1/desktop/releases/macos/<版本>/题库_<版本>_macOS_arm64.dmg`。只有工作流成功完成自托管发布后，这些地址才对应新版本。

Tauri 对 Windows 安装器提供的 `downloadBootstrapper` 模式不增加 WebView2 运行时包体，`offlineInstaller` 会增加约 127 MB。参考 [Tauri Windows 安装器文档](https://v2.tauri.app/distribute/windows-installer/) 和 [Tauri 更新器文档](https://v2.tauri.app/plugin/updater/)。

macOS GitHub Release 提供可直接安装的 `题库_<版本>_macOS_arm64.dmg`。自动更新仍使用签名的压缩归档 `qbank-macos-arm64-<版本>.app.tar.gz`，不使用 DMG；Windows 自动更新使用签名的 NSIS 压缩归档（`windows/tauri.conf.json` 的 `createUpdaterArtifacts` 设为 `v1Compatible`），GitHub Release 同时提供 `题库_windows_x64_setup.exe` 安装版和 `题库_windows_x64_portable.exe` 便携版。对应的 GitHub 下载地址为 `https://github.com/qingye0312-cpu/question-bank/releases/download/v<版本>/<文件名>`。当前 macOS 配置是 ad-hoc 代码签名；没有 Apple Developer ID 公证时，首次打开仍可能显示系统安全确认。

## GitHub 仓库配置

在仓库 **Settings → Secrets and variables → Actions** 添加以下内容。更新私钥必须沿用已发布客户端信任的原有密钥，不要重新生成。

### Repository variable

| 名称 | 内容 |
| --- | --- |
| `QBANK_UPDATER_PUBLIC_KEY` | `.local/macos-updater.key.pub` 的完整文本；这是 Tauri 更新器公钥，可以公开 |

### Repository secrets

| 名称 | 内容 |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | `.local/macos-updater.key` 的完整文本 |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | `.local/macos-updater.password` 的内容，去除首尾换行后原样粘贴 |

工作流在构建机内存中使用这些值签名；不把它们写进源码、Release、构建日志或自托管服务器。建议保护 `v*` 标签，只允许可信发布者创建，因为带签名密钥的工作流只应构建可信提交。

### 可选：自动部署到自托管小主机

未启用时，工作流仍会创建 GitHub Release，但不会更改小主机的 `latest.json`。启用后会同时部署两个平台的版本文件并切换服务端更新清单。

Repository variables：

| 名称 | 内容 |
| --- | --- |
| `QBANK_SELF_HOST_DEPLOY` | 填 `enabled` 启用 SSH 发布 |
| `QBANK_RELEASE_SSH_HOST` | 默认 `8.141.124.97`；如公网入口变化再修改 |
| `QBANK_RELEASE_SSH_PORT` | 默认 `8013` |

Repository secrets：

| 名称 | 内容 |
| --- | --- |
| `QBANK_RELEASE_SSH_KEY` | 能登录 `root@主机:8013` 的无密码 SSH 私钥；推荐单独创建部署密钥 |
| `QBANK_RELEASE_KNOWN_HOSTS` | 对应 `[主机]:8013` 的已核实 SSH 主机公钥行，不要使用未经核验的 `ssh-keyscan` 输出 |

发布账户需要 root 权限，因为安装脚本写入 `/var/lib/qbank-desktop-updates` 并设置 `root:caddy` 权限。部署脚本会校验清单版本、两端签名和不可覆盖的版本文件，随后从服务器本机通过 Caddy HTTPS 路由读取清单和更新归档。

## 发布步骤

1. 递增并同步 `package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` 和 `src-tauri/Cargo.lock` 的版本号。
2. 提交版本变更并推送到 `main`。
3. 创建并推送新版本标签，例如：

   ```sh
   git tag vMAJOR.MINOR.PATCH
   git push origin vMAJOR.MINOR.PATCH
   ```

4. 在 GitHub Actions 查看 `Desktop release`：macOS、Windows 构建成功后会生成 GitHub Release；如果已开启自托管发布变量，也会通过 SSH 部署并校验更新源。

不要用已有标签重发不同内容。服务端版本目录是不可覆盖的；如果构建内容需变更，请递增应用版本。

## 本机 macOS 构建

`pnpm release:mac` 仅在 Apple Silicon Mac 上构建本机 `.app` 和签名更新归档，不会发布更新清单，也不能替代跨平台 GitHub Release。正式构建配置为 `mac/tauri.conf.json` 与 `windows/tauri.conf.json`；Windows 安装版启用更新器归档并使用在线 WebView2 bootstrapper。
