# 桌面版构建、发布与自动更新

## 工作流结构

`.github/workflows/desktop-release.yml` 在 `v*` 标签触发后同时启动三个互不依赖的构建 job：

| Job | 产物 | 说明 |
| --- | --- | --- |
| `build-macos` | `qbank-macos` | macOS ARM64 App、DMG、签名更新归档和签名 |
| `build-windows-portable` | `qbank-windows-portable` | Windows x64 便携版，固定文件名 `题库_windows_x64_portable.exe` |
| `build-windows-installer` | `qbank-windows-installer` | Windows x64 NSIS 安装器、更新压缩包和签名 |

三个构建 job 不设置 `needs`。`publish` 使用 `needs: [build-macos, build-windows-portable, build-windows-installer]`，下载三个 artifact 到独立临时目录，再统一复制到 `release-assets`，生成 `latest.json` 和 `SHA256SUMS`，最后创建 GitHub Release，并按开关发布自托管更新源。

两个 Windows job 各自安装 pnpm/Rust 依赖、编译前端并使用独立 Rust cache key，避免互相覆盖；没有公共准备 job 阻塞并发启动。

## 本地验证

```sh
sh mac/scripts/env.sh node tools/desktop-release/validate-version.mjs v0.2.21
sh mac/scripts/env.sh pnpm exec tsc --noEmit
sh mac/scripts/env.sh pnpm test:platforms
```

工作流修改后验证 YAML 可解析、三个构建 job 均无 `needs`、`publish` 的 fan-in 完整，并运行 `git diff --check`。不自动 push。

## 签名和更新清单

签名私钥只由 GitHub Actions secret 或本机受保护环境提供，公钥作为客户端配置。发布阶段把 macOS 和 Windows 更新归档、`.sig`、DMG、安装器和便携版一起计算 SHA-256；更新器使用签名归档，便携版只供手动下载。

自托管发布需额外通过 SSH/SCP、服务端原子切换、HTTPS 清单读取和客户端安装更新检查。GitHub Release 成功不等于自托管清单或已安装客户端成功。
