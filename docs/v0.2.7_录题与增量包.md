# v0.2.7 大模型录题与增量包

本轮统一 Mac、Windows、小程序源码版本为 **0.2.7**。本说明描述代码能力，不代表安装包重新发布、小程序上传审核或飞书服务已上线。原有题库数据协议仍为 `1.0`，题库自身发布版本不随软件版本改写。

## 入口与操作

- 桌面端：侧栏「大模型录题」，或「设置与维护 → 大模型录题与增量包」。极速模式也可通过设置进入。「录题模板」和设置里均有「大模型输出规范模版」复制按钮。
- 小程序：展开首页搜索区，点击「大模型输出规范模版 · 复制」或「录题 / 增量包」。折叠后仍只保留一行搜索。
- 提示词只有复制按钮。给外部模型附上题目照片，由模型作答，回复应为一个 JSON 代码块。程序不会调用付费模型，也不会保留照片。
- 粘贴 JSON 或整个 `json` 代码块，点击「解析并比对题库」，检查题干、选项、答案、解析、模型名称／版本和识别提示，再确认保存。保存后可继续粘贴下一题；本批次持续累积新增题。
- 需要切开两次录入时点「新一批」。旧批次和上传标记可在重启后继续查看、补录和导出。

未知题型、未作答、残缺选项、错误答案引用、看不清占位、额外照片字段或非法 JSON 会阻止录入。结构校验通过不代表模型知识答案正确；实际模型版本无法确认时保留“未知”。

## 旧题比对

仅在所选题库内比对。题型、题干与选项内容相同视为同题；会处理选项调序，并按选项内容比对答案。只统一换行和首尾空白，不删除代码大小写、数字、否定词或标点，不做可能误判的模糊合并。

- 答案一致：显示已收录，跳过，不加入增量包。
- 答案不一致：录入页显示两份答案供核对，保留旧题；不在普通搜题列表添加冲突状态。
- 桌面回收站中的旧题也参与比对，不因重复粘贴而自动恢复。

## 增量包与上传标记

每批新题可保存为 **`题库名_批次.qbank-delta.json`**。文件内是完整标准题目 JSONL（包括模型来源和选项 UUID），外层含题库 ID、题库名、批次 ID、创建时间、题数和 SHA-256 内容校验值。

这是一份追加用文件，和整库替换用的 `.qbank.zip` 分开。只导出本批次仍在题库中的新题；旧题比对结果不进入包。内容校验用于发现损坏，不是发布者身份签名。

- 桌面：直接把增量包拖到窗口，或在「导入」中选择文件。按包内题库 ID 合并，无需提前选择目标题库。没有该 ID 时建立题库；已有时只追加新题，不覆盖或删除旧题。重复拖入不重复加题。答案或 ID 不一致的条目跳过并报告数量。
- 小程序：先点击「保存本批次增量包」，再点击「转发增量包给微信好友」。分成两步，使文件转发直接由用户点击触发。使用微信 `wx.shareFileMessage`，API 参考：[微信官方类型定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)。取消转发保留本地文件；真机和微信开发者工具的能力可能不同。
- 接收者：手机可在录题页点「从微信聊天导入增量包」，电脑可下载后拖入桌面端。
- 所有新题初始标记「待上传」。可以手动切换为「已上传（手动标记）」并改回。导出、微信转发、导入其他端均不会自动变成已上传飞书；本地上传标记不会随包传到别人设备。

飞书网络接入尚未完成，本轮不发送题目到飞书。微信 API 返回成功仅表示调用成功，接收情况请在聊天中确认。

## 小程序多题库

展开首页，点题库标题右侧「切换」。每库题目、搜索索引和录入批次按题库 ID 隔离，所选题库保存在本机；详情页也携带题库 ID，避免切库后查看错题。

「录题 / 增量包 → 新建题库」可建立「HarmonyOS 高级认证」等题库，也可通过聊天导入其他题库的增量包。当前只随包内置初级认证真实题目，没有虚构高级认证内容。

同名不代表同一题库。多人维护同一个高级认证题库时，应由一人创建后分享包，让大家沿用相同 ID；各自新建同名库会作为独立题库保留。

新题保存在微信用户文件目录，采用临时文件写入后改名，并校验本地记录；与内置压缩题库分开。清理小程序数据可能丢失尚未导出的新题，请及时导出转发。

## 人工验收

1. Mac、Windows 和小程序检查版本 `0.2.7`；分别复制提示词，粘贴到任意文本编辑器确认完整一致。
2. 录入一道全新的单选，再录入多选和判断；搜索应立即可见，退出重开后题目和批次还在。将同题选项调序并调整答案字母，确认不会重复新增。
3. 在初级库与新建高级库分别录入带唯一关键词的题目，反复切换并打开详情，确认搜索和答案属于当前库。
4. 导出本批次，拖到另一台桌面端两次：第一次新增，第二次不增题；其他题库不受影响。手动修改包内题干但不改校验值，应拒绝导入。
5. 手机先保存增量包，再转发给好友或文件传输助手；接收端导入后题目和模型版本应完整。取消转发、重复转发均不改变上传标记。
6. 手动标记上传，再导出／转发／重启，确认本机标记保留，接收端仍显示待上传。

## 开发维护

提示词源文件：`templates/大模型拍照识题_单题输出提示词_v1_草案.txt`；旧批量提示词原样保留。`shared/intake.ts` 是客户端共同规则；`scripts/sync-client-assets.mjs` 同步三端提示词、应用版本和小程序逻辑副本，生成的小文件随仓库提交，开发者工具可直接编译。

常用检查：

```sh
pnpm test:intake
pnpm check:miniprogram
pnpm build
cargo test --manifest-path src-tauri/Cargo.toml --test intake --test core
```

本轮的微信转发、Windows 剪贴板和三端界面体验由用户实机验收；编译与数据回归不代替这些检查。
