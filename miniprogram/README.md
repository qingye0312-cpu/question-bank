# 微信小程序：内置题目、运行时索引实验版

## 当前实验结果（2026-10-15，优先于以下历史记录）

分支 `codex/embedded-runtime-index`，从 `69a9573` 创建；原局域网下载版保留在 `codex/organize-platforms`。

- 代码包仅内置 `data/questions.json` 与 `data/manifest.json`，不包含 `data/index.json`。原始题目、答案及元数据不裁剪；预生成索引保留在源码中用于一致性测试及旧服务器。
- 首次读取题目后按 32 题一批生成索引，批次间让出执行权；缓存到用户目录 `qbank-runtime-index-v1.json`。索引按 schema、题库 release_id、题数和校验值验证，过期或损坏自动重建。先写临时文件再改名；写缓存失败仍可使用本次内存索引。
- 本分支没有题库下载调用，不依赖临时服务器。旧下载缓存保持不动。题库版本变化时自动重建索引；索引算法变更需同步升级缓存协议。
- 微信开发工具 2.02.2610142 的实际预览打包成功，预览面板显示 **1321 KB**，通知显示 **1.3 MB**，满足小于 1.5 MB 的目标。这是工具显示值，未将取整后的 KB 换算成声称精确的字节数。仅生成预览包，没有提交审核或发布正式版。
- 模拟器一次无索引缓存启动：读取 37 ms，索引生成 395 ms，保存 41 ms，题库准备合计 **473 ms**。一次缓存启动：读取 39 ms，索引读取校验 29 ms，合计 **68 ms**。这是 `loadBank` 的计时，不包含微信启动、代码包获取、页面绘制，不是统计 P95。
- 用户反馈“真机测试和延迟没有问题”；记录为人工体验验收，未给真机搜索耗时编造毫秒数。
- 类型检查及 11 项回归通过，包括运行时与预生成索引完全一致、失败重试、缓存复用、缓存损坏重建及写入失败仍可搜索。

复测：备份用户目录下的索引缓存后重新编译，在 Console 查看 `[qbank startup]`；`source: generated` 为首次生成，`source: cache` 为缓存启动。普通 `loadBank` 重复调用共享内存 Promise，不算冷启动。开发工具“无依赖文件”检查可能把通过文件系统读取的内置 JSON 当作无依赖资源；这两份资源已显式列入打包 include，不能据此移除。下方下载版和早期内置版记录仅供追溯。

## 当前运行方式（2026-10-15 更新，优先于下方内置版历史记录）

仓库根目录执行以下命令启动当前局域网测试服务器（保持进程及电脑运行）：

```sh
BANK_HOST=192.168.100.117 sh mac/scripts/env.sh pnpm serve:miniprogram
```

手机和电脑连接同一可信局域网，下载地址为 `http://192.168.100.117:8765/bank.json`。服务仅绑定指定网卡地址，只提供 `/bank.json` 和 `/health`，不会暴露仓库其他文件。未指定 `BANK_HOST` 时仅监听 `127.0.0.1`，不能供手机使用。IP 变化后需同步修改 `miniprogram/services/bank.ts` 的开发端点并重新编译。终端 Ctrl-C 可正常停止；端口占用时检查原实例，不重复启动或结束未知进程。服务输出请求时间、来源地址、路径与状态码，用于区分手机实际下载和缓存命中。电脑休眠或网络切换会影响服务，本工具不安装系统常驻服务。

手机浏览器可先打开 `http://192.168.100.117:8765/health`，预期返回 `status: ok`；若失败，先检查同一 Wi-Fi、客户端隔离及系统网络权限，不要直接关闭防火墙。开发者工具重新编译后首次下载 914 题，验证资源格式、题数和索引版本后保存到用户目录；以后优先读缓存，可关闭服务器离线搜索。读取或下载失败可点击重新加载。损坏下载不会写入正式缓存。

`data/` 保留为服务器数据源，但通过 `packOptions.ignore` 排除出小程序代码包；JS、WXML、WXSS 压缩已开启。用户已授权仅本地调试关闭本机私有配置的 `urlCheck`，项目公共配置不放宽网络校验。真机不能使用电脑的 loopback 地址。此 HTTP 服务无鉴权、无加密，只用于可信局域网临时测试，不做路由器端口映射或公网部署。

## 直接运行

1. 微信开发者工具打开当前目录 `question-bank/miniprogram/`，即包含 `project.config.json` 的目录。不要把里面的 `miniprogram/` 子目录当工程根目录。
2. 使用工程中现有 AppID，点击「编译」。入口是 `pages/index/index`。工程已关闭开发／上传时的无依赖文件过滤，并显式包含 `data/`；本机私有配置只同步关闭了开发过滤，避免漏掉运行时读取的题库文件。
3. 页面应显示题库名、914 道题、内置版本 1。输入文字可即时搜索，清空可查看全部题目。
4. 点击「预览」，由开发者／体验者在手机上验证。当前未替用户上传体验版或发布正式版本。

构建生成的题库文件已随源码保存，首次运行不需要先安装 npm 依赖或启动服务器。小程序代码包本身仍需要微信获取；离线使用以微信允许正常启动为前提。

## 当前能力

- 输入和普通文字粘贴；空格分隔多个词同时匹配，英文双引号表示连续短语。
- 题干、选项、标签、章节、编号和题目 ID 可搜；解析和答案不参与检索。
- 单字、双字、中英文和 NFKC 规范化；300 字／12 个词限制有明确提示。
- 每个搜索词稳定配色，较远的命中片段仍显示；点击查看完整题干、全部选项、答案和已有解析。
- 连续滚动、可变高度虚拟列表；只把当前视口和缓冲区的数据传给页面。
- 输入变化使旧查询失效；内置读取错误可重试，空结果和超限均有提示。

暂未接入题库下载、后台更新、云服务、鉴权、加密、拍照／截图识题、编辑或制包分享。内置版不代表已通过 1 万／10 万题、最低支持系统或 P95 ≤ 200 ms 的真机验收。

## 更新内置题库与检查

以下命令在 `question-bank/` 仓库根目录执行，使用已有 Node.js 22.18+ 和锁文件中的 TypeScript：

```sh
pnpm prepare:miniprogram
pnpm check:miniprogram
pnpm test:miniprogram
```

本机可使用仓库工具链入口：`sh mac/scripts/env.sh pnpm check:miniprogram`。生成器默认使用桌面内置源 `src-tauri/resources/seed.json`，不自动读取桌面应用本机数据库中的维护记录。

从桌面维护后的题库生成时，先在桌面「制作离线包」，将 `.qbank.zip` 解压到独立目录，再运行：

```sh
node tools/mobile-index/build.mjs --source /absolute/path/to/unpacked-bank
node tools/mobile-index/build.mjs --check --source /absolute/path/to/unpacked-bank
```

随后重新编译小程序。此方式保留 JSONL 原始字节、题库 ID、内容版本、哈希、题目和选项 ID。使用自定义发布包后，校验也需传相同 `--source`；默认 `prepare:miniprogram` 会恢复为仓库默认内置题库。

当前生成文件：标准 `data/manifest.json`、内置资源 `data/questions.json`，以及绑定相同内容哈希的 `data/index.json`。914 题合计 1,866,902 字节（约 1.78 MiB）；这是未压缩数据大小，不是微信最终上传包大小。生成器设置 1900 KiB 数据预算并拒绝超限，实际上传体积以开发者工具为准。

微信开发者工具 2.02.2610142 / 基础库 3.17.4 实测直接读取代码包内 `.jsonl` 和 `.txt` 会报 `permission denied`，因此使用 JSON 字符串封装：`{"format":"qbank-embedded-jsonl-1","payload":"原始 JSONL 文本"}`。加载时解码后再按行读取，不重新序列化题目；解码后的 UTF-8 字节与桌面 `questions.jsonl` 一致，标准清单中的逻辑文件名、内容 SHA-256 和外部 `.qbank.zip` 协议均不变。该封装只适配小程序内置资源，并非新交换格式或加密。

数据统一及加密方案见 [评估文档](../docs/三端统一题库格式与加密评估.md)。当前数据未加密；差分编码只是索引体积优化。
